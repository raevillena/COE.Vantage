## MMSU Grade Push (Experimental Browser Extension)

- **What:** a Chrome/Edge extension (Manifest V3) that fills the MMSU portal gradesheet (`my.mmsu.edu.ph/my/class/gradesheet/*`) from a table pasted out of Excel / Google Sheets, then re-reads the portal and reports whether it matches the sheet. Replaces the server-side Puppeteer approach of the old `gradesheet_updater` project: it runs in the user's own logged-in tab, so Vantage never holds portal credentials or grades.
- **Where:** `frontend/extensions/mmsu-gradesheet/` (`src/paste.ts` table parsing + column detection, `grade.ts` grade -> portal option, `portal.ts` reads the gradesheet form, `plan.ts` source vs portal diff, `fill.ts` apply + verify, `job.ts` keeps the fill across the reload that saving causes, `panel.ts` shadow-DOM UI).
- **Build:** `npm run build:extension` (in `frontend`) type-checks, bundles with esbuild into `extensions/mmsu-gradesheet/dist` (git-ignored) and writes `public/downloads/vantage-mmsu-grade-push.zip`, which **is committed** (fixed timestamps, so unchanged sources give identical bytes) and served by the app. Bump `version` in `manifest.json` and `EXTENSION_VERSION` in the page when the extension changes.
- **Feature flag:** `mmsuGradePush` (backend `experimentalFeatures.ts` + `authSchemas.ts`, frontend `featureCatalog.ts`, `types/auth.ts`). Off unless enabled on the Profile page. Page: `/experimental/mmsu-grade-push` (`ExperimentalMmsuGradePushPage.tsx`, setup and usage steps).
- **Portal facts it relies on** (from saved portal pages): one `<form action=".../gradesheet/update/<id>">`; rows have `select[name^=grade_]` whose options are 1.00-3.00 in .25 steps, 4.00, 5.00, INC, DRP, IP and `0` for "---"; the student number is in the "Student Number" column; Save is `[name=savegradesheet]` (next to `removestudents` and a separate reset form, which are never touched); after saving the portal shows the same form with the grades selected and a `.alert-flash` "Gradesheet Updated". Remarks are computed client-side by the portal from the dropdown.
- **Safety rules in the code:** match by student number only (a differing name only warns and leaves the row unticked); grades the dropdown does not offer are refused, never rounded; blank cells never clear a grade; conflicting duplicates are refused; the result check also lists rows that changed without being asked.
- **Tests:** `frontend/tests/e2e/mmsuPush.spec.ts` loads the built extension into Chromium against a fake portal (made-up students; every request that is not the fake portal is aborted and fails the test). It needs no Vantage backend. `smoke.spec.ts` has the module-page test.
- **Not verified:** a real logged-in portal session. Saved page samples (`portal_*.txt`, git-ignored, contain real student data) were used to confirm the markup, not a live save.

### Vantage access check (extension v0.2.0)
- The panel is gated: `panel.ts` asks `access.ts` -> background worker -> `GET {api}/auth/extension-access/mmsu-grade-push` (credentials include, i.e. the Vantage login cookie; host_permissions in `manifest.json` cover the production API and localhost/127.0.0.1). Backend: `getExtensionAccess` in `authService.ts` reads the refresh cookie **without rotating it**, returns `{allowed, reason: signed_out | role | not_granted | not_enabled}` and no token. Allowed = role fits + admin granted `mmsuGradePush` + user switched it on.
- Positive answers are cached 10 minutes in `chrome.storage.local`; failures close the panel with "Check again". It is an access list, not a security boundary (the extension runs locally).
- Build-time `VANTAGE_API_URL` (default `https://vantage.api.nbericmmsu.com`); storage key `vantage-api-url` overrides it (the tests use it).
- Icons in `extensions/mmsu-gradesheet/icons/` come from the site favicons.
- **Not verified:** the cookie being sent cross-site in production (site and API are different hosts, cookie is `SameSite=Lax; Secure`). Chrome sends it for extensions with host permission, but test it once on the real deployment.
- Tests: `mmsuPush.spec.ts` (gate states, Check again, no portal leaks), `experimentalAccess.spec.ts` (endpoint reasons, no rotation).
